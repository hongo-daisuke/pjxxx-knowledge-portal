## 指示 b: kb_filter の「コメントアウト保存」を「生きた実装」に変更 (優先度: 高 / 作業量: 中)

### 問題

v2 では P2 用の `orAll` ロジックをコメントアウトで残し、対応するテスト 4 本に `@pytest.mark.skip` を付けている。コメントアウトされたコードと skip されたテストは、周辺実装の変化に追随せず **P2 で復活させた時点で動かない** リスクが高い。

### 方針

**orAll 版は生きた関数・生きたテストとして常時維持し、P1 の制約は「公開関数の配線」だけで表現する。**

### 作業

`backend/layer/library/python/shared/kb_filter.py` を以下の構成に変更する (関数名は既存実装に合わせて調整可):

```python
_PUBLIC_ONLY_FILTER = {"equals": {"key": "visibility", "value": "public"}}

def build_full_filter(department: str, user_sub: str) -> dict:
    """権限フィルタ完全版 (public ∪ 自部署 ∪ 自分の private)。
    P2 (F-303) で build_retrieval_filter からの配線を切り替える。
    """
    return {"orAll": [
        {"equals": {"key": "visibility", "value": "public"}},
        {"andAll": [
            {"equals": {"key": "visibility", "value": "department"}},
            {"equals": {"key": "department", "value": department}},
        ]},
        {"andAll": [
            {"equals": {"key": "visibility", "value": "private"}},
            {"equals": {"key": "ownerId", "value": user_sub}},
        ]},
    ]}

def build_retrieval_filter(user_ctx) -> dict:
    """chat_service から呼ばれる公開関数。
    Phase 1: visibility=public 固定 (安全側)。
    Phase 2: return build_full_filter(user_ctx.department, user_ctx.sub) に切り替え。
    """
    return _PUBLIC_ONLY_FILTER
```

`backend/tests/unit/chat/test_kb_filter.py`:

1. **skip マークを全て外す**
2. P2 用テスト 4 本は `build_full_filter()` を直接テストする形に書き換える (公開関数経由ではなく)
3. 公開関数のテストは「P1 では常に public 固定フィルタを返すこと」を検証する
4. コメントアウトされたコード断片が残っていれば削除する

### 受入条件

- `pytest` が **skip 0 件** で全テスト green
- `kb_filter.py` 内にコメントアウトされた実装コードが存在しない
- P2 移行時の変更が「`build_retrieval_filter` の return 1 行 + E2E 追加」で済む構造になっている

## 指示 d: テスト実行に必要な依存関係の追加 (優先度: 高 / 作業量: 小)

v2 で vitest 設定 (`environment: 'jsdom'`) と humps によるケース変換を導入したが、package.json への依存追加が修正記録にない。不足していると `npm run test:unit` が起動時に落ち、**指摘 2 で防ごうとした「CI 初回失敗」がそのまま起きる**。

### 作業

1. `frontend/package.json` を確認し、不足していれば追加する:
   - dependencies: `humps`
   - devDependencies: `@types/humps`, `jsdom`
2. `vite.config.ts` の `test.globals: true` を使う場合、`tsconfig.app.json` (または vitest が参照する tsconfig) の `compilerOptions.types` に `"vitest/globals"` を追加する。もしくは globals を使わず各 spec で `import { describe, it, expect, vi } from 'vitest'` に統一する (どちらかに揃えること)
3. `npm install` 後、以下をローカルで実行し全て成功することを確認する:
   - `npm run lint`
   - `npm run type-check` (存在する場合)
   - `npm run test:unit`

### 受入条件

- クリーンな `npm ci` から `test:unit` までが一発で green
- lockfile (`package-lock.json`) の更新がコミットに含まれている
