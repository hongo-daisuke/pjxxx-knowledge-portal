## 指示 c: 設計書反映タスクの消化

### 変更ファイル

| ファイルパス | 変更内容 |
|---|---|
| `docs/md/03_詳細設計書.md` | ① `nextToken` → `next_token` (GET /documents クエリパラメータ) ② `"sessionId"` → `"session_id"` (POST /chat リクエスト例) ③ `"docId"` → `"doc_id"` (POST /chat レスポンス citations 例) ④ Lambda 設計の「Logger, **Tracer**, Metrics」から Tracer を削除 (CLAUDE.md 規約: X-Ray SDK EOS 対応で Tracer 不使用) ⑤ `features/auth/stores` → `shared/stores/useAuthStore` の記述に修正 |
| `docs/md/06_フロントエンド構成図.md` | ① `features/auth` から `stores/` サブディレクトリを削除 ② `shared/` に `stores/` (`useAuthStore`) を追加 ③ §5 の「`features/auth` の `useAuthStore`」→「`shared/stores/useAuthStore`」に修正 |

### 受入条件の充足確認

| 条件 | 結果 |
|---|---|
| 03 の API 例フィールドが snake_case になっている | ✅ (`doc_id`, `session_id`, `next_token` に修正) |
| 06 の `useAuthStore` 配置が `shared/stores/` になっている | ✅ |
| `kb_filter.py` のフィルタキー名と `s3util.py` の metadataAttributes キー名が一致 | ✅ (`"ownerId"` で完全一致、単体テストで担保) |

### 補足: metadataAttributes キーは snake_case 変換の対象外

`metadata.json` の `metadataAttributes` キーは AWS Bedrock Knowledge Base の仕様に従った KB 固有の識別子であり、Lambda→フロントエンド間の API ワイヤー形式 (snake_case) とは独立している。axios インターセプターの camelCase↔snake_case 変換は HTTP ボディにのみ適用され、Lambda 内部で S3 に書き込む KB メタデータには適用されない。そのため `"ownerId"` は camelCase のまま維持する。
