## 1. 背景・目的

### 1.1 背景

- 社内ドキュメント (手順書・議事録・設計書・規程類) が個人フォルダ・チャット・メール添付に分散し、必要な情報に到達できない
- 既存の全文検索は「キーワードが一致する文書」しか見つけられず、「〜のやり方を知りたい」という質問形式のニーズに応えられない
- 生成 AI (RAG) による社内文書 QA はニーズが高いが、ベクトルストア (OpenSearch Serverless) の常時課金がネックで PoC 止まりになっていた

### 1.2 目的

1. 社内ドキュメントを **権限管理・タグ付け・版管理付きで一元管理** する
2. Amazon Bedrock Knowledge Bases + **S3 Vectors** により、**低ランニングコスト** で「社内文書に質問できる」RAG チャットを提供する
3. 文書管理側で付与した権限メタデータを RAG 検索時のフィルタに連動させ、**閲覧権限のある文書だけが回答根拠になる** ことを保証する

### 1.3 本システムで解決しないこと (スコープ外)

- 文書の共同編集 (Office/Google Docs 的な編集機能)。本システムは「完成した文書の登録・検索・活用」に特化する
- 全社 SSO 基盤の構築 (既存 IdP=Okta との連携は行うが、IdP 自体の構築は対象外)
- リアルタイム性が要求される大量同時アクセス (社内利用・数十〜数百人規模を想定)

## 2. 利用者と権限

| ロール | 想定利用者 | できること |
|---|---|---|
| viewer | 全社員 | 閲覧権限のある文書の検索・閲覧・ダウンロード、RAG チャット |
| editor | 各部署の文書管理担当 | viewer + 文書の登録・更新・タグ付け・公開範囲設定 |
| admin | 情報システム部門 | editor + 全文書の管理、KB 同期の手動実行、監査ログ閲覧、タグマスタ管理 |

ロールは Cognito ユーザープールのグループで管理する。

### 2.1 公開範囲 (visibility)

| 区分 | 閲覧可能な範囲 |
|---|---|
| public | 全社員 |
| department | 所属部署のメンバーのみ |
| private | 登録者本人のみ (下書き用途) |

公開範囲は RAG チャットの検索対象にも同一のルールで適用される (要件 R-11)。

## 3. 機能要件 (サマリ)

詳細は「04 機能一覧」を参照。ここでは要件レベルの一覧のみ示す。

| ID | 要件 | 優先度 |
|---|---|---|
| R-01 | ユーザーは Cognito (Hosted UI) でログインできる。Okta SAML 連携に対応できる構成とする | MUST |
| R-02 | editor は文書ファイル (PDF/Word/Excel/PowerPoint/Markdown/テキスト) をアップロードできる | MUST |
| R-03 | 文書にはタイトル・説明・タグ (複数)・部署・公開範囲を設定できる | MUST |
| R-04 | 文書はタグ・部署・キーワード (タイトル/説明) で検索・絞り込みできる | MUST |
| R-05 | 文書は presigned URL でダウンロードできる (S3 を直接公開しない) | MUST |
| R-06 | 同一文書の再アップロードで版が積み上がり、過去版を参照できる | SHOULD |
| R-07 | 文書の登録・更新・削除・ダウンロードは監査ログに記録される | SHOULD |
| R-08 | 利用者は自然言語で質問し、社内文書を根拠とした回答を得られる (RAG チャット) | MUST |
| R-09 | RAG 回答には根拠文書 (出典) へのリンクを表示する | MUST |
| R-10 | 文書の追加・更新・削除は Knowledge Base へ自動同期される | MUST |
| R-11 | RAG 検索は質問者の閲覧権限内の文書のみを対象とする (メタデータフィルタ) | MUST |
| R-12 | admin は KB の同期状態を確認し、手動同期を実行できる | SHOULD |
| R-13 | チャット履歴を利用者ごとに保存・参照できる | COULD |

## 4. 非機能要件

| 分類 | 要件 |
|---|---|
| 性能 | 文書一覧・検索: 2 秒以内 / RAG 回答: 15 秒以内 (S3 Vectors の検索レイテンシ + LLM 生成を許容) |
| 可用性 | 営業時間内 99% (サーバーレス構成のマネージド SLA に準拠、独自の冗長化は行わない) |
| コスト | **アイドル時の固定費を月額 1,000 円未満** に抑える。ベクトルストアに常時課金型 (OpenSearch Serverless 等) を採用しない |
| セキュリティ | S3 バケットは全てパブリックアクセスブロック。API は Cognito オーソライザ必須。IAM は最小権限・`${AWS::Partition}` 使用 |
| 監査 | 文書操作ログを 1 年保存 (DynamoDB TTL + 必要に応じ S3 エクスポート) |
| 運用 | IaC (AWS SAM) 管理・GitHub Actions による CI/CD (`cicd-template-learn` テンプレート準拠)。dev/prd 2 環境 |
| 拡張性 | 検索頻度が増大した場合、S3 Vectors → OpenSearch Serverless へエクスポートして移行できる構成とする |

## 5. 制約事項

1. AWS サーバーレス構成 (Lambda / API Gateway / DynamoDB / S3) を採用する。社内標準の bastion アカウント + ロールチェーンパターンに対応する
2. フロントエンドは Vue 3 + TypeScript、バックエンドは Python 3.13 (Lambda Powertools) とする
3. Bedrock の利用モデル (埋め込み・生成) は利用リージョンでの提供状況を構築時に確認する。S3 Vectors が東京リージョン未提供の場合、KB 関連リソースのみ提供リージョンに配置する構成を許容する
4. Knowledge Bases のベクトルストアは **S3 Vectors を必須** とする (クイック作成の既定値である OpenSearch Serverless を選択しない)

## 6. 成功基準

- dev 環境で文書 100 件を登録し、権限別ユーザー 3 種で「閲覧権限外の文書が検索・RAG 回答の根拠に一切現れない」ことを確認できる
- ベクトルストア関連の月額固定費が数百円以下であることを Cost Explorer で実証できる
- CI/CD テンプレートの全ワークフロー (lint / test / E2E / deploy) が本システムで成立する
